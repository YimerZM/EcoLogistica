## 1. Alternativas

| Alternativa | Interfaz | API | Categoría de base de datos evaluada |
|---|---|---|---|
| A1 MERN | React | Node.js y Express | Documental (MongoDB) |
| A2 Python | React | FastAPI | Relacional (PostgreSQL) |
| A3 Java | Angular | Spring Boot | Relacional (PostgreSQL) |

La categoría de base de datos no es un criterio fijo a favor de lo relacional. Se elige después de mirar la tarea: pedidos, vehículos y rutas se relacionan y exigen claves e integridad. Por eso se compara una opción documental con dos relacionales, y el puntaje sale de ese análisis.

## 2. Matriz

Escala de 1 a 5. En «categoría de base de datos», 5 significa que la categoría encaja con la tarea analizada.

| Criterio | Peso | A1 MERN | A2 Python | A3 Java |
|---|---:|---:|---:|---:|
| Curva de aprendizaje | 20 % | 5 | 4 | 2 |
| Costo de infraestructura | 15 % | 4 | 4 | 3 |
| Soporte comunitario | 10 % | 5 | 4 | 5 |
| Categoría de base de datos | 25 % | 3 | 5 | 5 |
| Concurrencia esperada del MVP | 10 % | 5 | 3 | 4 |
| Eco-diseño en carga baja | 20 % | 3 | 4 | 3 |

La categoría de base de datos pesa más porque la tarea exige integridad entre pedidos, vehículos y rutas. La concurrencia pesa menos porque el MVP no es un sistema de alta concurrencia.

Un stack Python no es eficiente cuando hay miles de conexiones simultáneas: en ese criterio queda en 3, por debajo de Node.js. RNF-008 fija el umbral en 50 usuarios. Con esa carga, el 3 no anula la decisión. Si el producto pasara a alta concurrencia, A1 debería reevaluarse.

| Alternativa | Cálculo | Total |
|---|---|---:|
| A1 MERN | 5×0.20 + 4×0.15 + 5×0.10 + 3×0.25 + 5×0.10 + 3×0.20 | 3.95 |
| A2 Python | 4×0.20 + 4×0.15 + 4×0.10 + 5×0.25 + 3×0.10 + 4×0.20 | 4.15 |
| A3 Java | 2×0.20 + 3×0.15 + 5×0.10 + 5×0.25 + 4×0.10 + 3×0.20 | 3.60 |

## 3. Decisión

Se selecciona **React + FastAPI + PostgreSQL**.

La categoría relacional gana el análisis de la tarea: hay claves primarias, alternas y foráneas entre usuario, pedido, vehículo y ruta. MongoDB queda descartado para el núcleo transaccional, no porque «relacional» fuera un criterio previo. FastAPI se acepta porque la concurrencia del MVP es baja. La ventaja de Node en alta concurrencia no compensa, en este alcance, la curva y el modelo de datos.

Stack de desarrollo:

| Capa | Tecnología |
|---|---|
| Interfaz | React |
| API | Python con FastAPI |
| Base de datos | PostgreSQL |
