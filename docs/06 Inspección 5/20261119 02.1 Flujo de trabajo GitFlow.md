## 1. Ramas que ya existen

| Rama | Uso | Estado al 2026-11-19 |
|---|---|---|
| `main` | Entrega que ve el docente | Publicada en `origin/main` |
| `develop` | Integración del equipo | Creada y publicada. Coincide con `main` hasta el cierre anterior |
| `feature/US-000` | Una historia | Sale de `develop` y vuelve a `develop` |
| `release/vX.Y.Z` | Cierre de una versión | Sale de `develop` y se fusiona en `main` y en `develop` |
| `hotfix/` | Corrección sobre `main` | Reservada. No hay un hotfix abierto |

El flujo se inició con `git flow init -d`. `main` es la rama de producción del flujo y `develop` es la de integración. Los prefijos son `feature/`, `bugfix/`, `release/`, `hotfix/` y `support/`.

## 2. Secuencia de la siguiente historia

1. `git checkout develop`
2. `git pull origin develop`
3. `git flow feature start US-008`
4. Commits pequeños. El mensaje cita la historia.
5. `git flow feature finish US-008` cuando pasen `tests.test_reglas` y `tests.test_e2e`.
6. Al cerrar una versión, `git flow release start v1.2.0`, probar, y `git flow release finish v1.2.0`.

## 3. Lo que no se hace

No se hace push directo de una historia sin terminar a `main`. No se usa `push --force` sobre `main` ni sobre `develop`. No se reescribe el historial ya publicado. No se suben `__pycache__`, `.env` ni `node_modules`.
